Title:
Beyond the Prompt: Engineering Your Codex Workflow

Description:
This presentation explores how Codex projects, context, instructions, hooks, rules, skills, and sub-agents can work together in software development. Through a test first implementation demo, you’ll see several sub-agents collaborate to plan a feature, write tests, implement and review the change, and verify the result.

---------------

Reseting the Context

- Does a new thread (conversation) mean losing all context?
That is not always a bad thing. Often you need to drop irrelevant context and carry forward only what matters for this task.

https://codexhandbook.com/en/guide/foundations/tokens-context-and-compaction/
- Compaction
The context is compacted after some time (zipped), and there is a sweet point for the context to work the best - around 200k-400k tokens
So because of this, maybe it is best for each new task to start a new thread!
And all the important things to be written in the agents configuration files (agents md), documentation (like readme, or separate docs folder with specific documentation).

Hallucinations and drift are often context prblem too!! Because the agents are bloated with lot of context, and lot of compacted context and that is causing missunderstanding.
	- Analogy: everything the agent think is written on the wall - so the more writtings ends up on the wall it just start to overhelmed (so when it compact, it is erasing some of them and summarizing it - so it's just a simple compression)
So something this can be "fixed" with sub-agents, because they will have their own context, not poluted with lot of not needed context - and care only about specific things (not get confused about lot of different things).
	- so it's important the agent to not load bunch of not needed things about that specific task because they will get confused

---------------

Skills vs custom sub-agents

- skill is a repeatable task/process/instruction that you can invoke
- skill is like instruction playbook, to the the things in some order (instruction prompt that could have an input)

---------------

Review skills weekly?

New models come and if the skill is too primitive, it will be counter-intuitive for a really smart model to use a stupid skill.

---------------

Sub-agents orchestration

1. Part of the prompt
2. Part of the AGENTS.md (for a specfic type of work)
3. Part of a specific reusable skill (for some repeatable behaviour)

---------------

Goals

* used for loong run tasks - several hours - whole day
* not used for well defined prompts (with verification steps, and all the other tech details) that will be executed in several minutes

---------------

Instructions

- Put the instruction where they apply (the whole repo could have multiple projects, domains, etc, each of them could have separate AGENTS.md)
- Keep rules short. Link to plans, docs, and tests.
- The agents md should not be more than 300 lines

* hooks and rules won't be written here (these instructions are not DETERMINISTIC)

---------------

Examples

Hooks

- We want DETERMINISTIC pre model execution
	* git fetch and git pull if new changes remote
- We want DETERMINISTIC post model execution
	* run npm tests, linter, etc

Rules

- We want DETERMINISTIC restrictions for some commands, like:
	* git reset - block always
	* git push - ask first 

---------------

Using AI coding agents (harnesses)
1. Most Important Skill: Clear communication and precise thinking - explain exactly to the AI what you want and what’s important.
2. Create a Good Environment: Clean codebases and tests are crucial (“garbage in, garbage out”); specifications that focus solely on theory without considering code often fail.
3. Uncover Unknown Gaps: Be aware of “unknown unknowns - by having the AI interview you before it builds anything.
4. Trust Ladder: Don’t trust blindl - start small, monitor closely, and only gradually grant more autonomy.
5. Delegate routine tasks: Use AI primarily for boring, repetitive tasks so you can focus on what matters most.
